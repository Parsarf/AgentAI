## Work and completion criteria

Close the old personal-agent implementation gaps for the customer product, reusing proven native configuration and artifacts.

1. Preserve trusted orchestrator/researcher/browser/critic roles; inspect effective tool ceilings across all layers. Researchers/browser workers cannot spawn, send, schedule, change policy or access customer credentials/private memory. Sourced research needs at least two primary sources supporting material claims, attributed uncertainty and actual no-effect injection evidence.
2. Complete the native Codex build/debug path and independent ACP review path. Inventory execution identity, writable roots, network, inherited env, auth and billing for each harness. A host-side ACP process is not protected by Gateway sandbox policy. Require builder/reviewer confinement; reviewer source is read-only with separate scratch. Missing safe supported isolation/auth blocks activation.
3. Reuse/create orchestration, deep-research, browser-task, software-project, debugging, untrusted-content and skill-improvement procedures. Builder tasks define objective/revision/allowed changes/budget/tests/artifacts; reviewer sessions receive a final snapshot/spec/evidence without builder conversation. Disposition every finding. Trivial work stays direct.
4. Scope native memory to customer/project as the contract requires. Use source/date/confidence/last-confirmed conventions where schema is unavailable, selective retrieval, correction/deletion/index invalidation and explicit backup/history retention. Large tool results become referenced artifacts. Outside claims never become instructions.
5. Complete supported durable objective/controller integration; distinguish persisted goal records from autonomous restart execution. Map actual native states to app states, persist checkpoints/receipts, reconcile uncertain effects before resume, and make cancellation sticky across children/jobs/restarts. Unsupported autonomy must be recorded as a launch gap or explicitly narrower contract, not called implemented.
6. Configure supported scheduling/timezones/timeouts/cheap-first checks with stricter unattended authority and per-task budget admission. The installed scheduler's reported capacity of eight is a historical limit to verify; do not invent a concurrency-one native field. Unattended approval unavailable/expired means deny or safely wait. Do not enable new customer schedules before enforcement proof.
7. Carry forward legacy per-customer reusable skills and watchers using supported
native mechanisms: create/list/search/run/version a skill within its tenant;
propose revisions for review, never apply policy changes automatically. Watchers
persist last-observed state and use a cheap deterministic unchanged check before
model escalation; unchanged means zero model calls. Changed checks respect task
budget/authority, deduplicate notifications and survive restart without duplicate
jobs. Define fixture assertions for unchanged/changed watchers, skill reuse and
cross-tenant skill/notification access. If not launch-required, retain these in
the later-release ledger with a concrete dependency and acceptance case.
8. Prepare the old app-board build/browser/review and seeded ID-zero debug regression; memory preference plus 12 unrelated facts/correction/deletion; three-step restart/ambiguous-checkpoint/cancel; no-change schedule/timezone/approval cases. Heavy/paid/native workflows run in Phase 15, not merely by executing this build prompt.

Deliver missing native configuration/controller wiring, customer scope, procedures and fixtures. Done when required selected capabilities are built and policy/config checks pass; every unrun or unsupported behavior is mapped to a case/blocker.
