# Component selection

Use plain text for simple answers. Choose the smallest useful composition when structure helps exact comparison, pattern recognition, exploration, data entry or execution monitoring.

- Tables show exact values; charts show patterns and have data-table alternatives.
- Cards describe entities; collections compare several entities without repeating them in prose.
- Forms collect related inputs. Inputs can include multi-select, ranges, dates, ratings, tags and autocomplete. A wizard stages a long questionnaire.
- Decision tools use bounded named arithmetic, weighting, compounding, budget or rule operations. No executable expressions are accepted.
- Monitoring widgets read real task events, phase dependencies, native plan state and provider receipts. Missing token counts remain unavailable. Reservation-bound cost fallbacks are labeled estimates.
- Calendar, Kanban, recurrence and time-tracking edits are local artifact state. A schedule draft does not create a job; a reservation selection does not book a table. File upload enters the account's existing scanned Files flow.
- Maps can explore supplied coordinates, layers and great-circle distances. Tiles, road routing, geocoding and street imagery require a configured provider and must be labeled unavailable otherwise.
- Domain adapters render sourced results and observation times; never label illustrative or unverified values live.
- Update the existing artifact during a continuing interaction. Preserve stable node ids and compatible user input.

Basic answers carry no composed document. Medium allows information and local exploration, but rejects agent actions/forms/approval controls. Interactive permits all registered capabilities with backend authorization. Detailed schemas/examples are retrieved on demand from the same generated registry; they are not injected every turn.
