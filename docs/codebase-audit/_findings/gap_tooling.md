## Findings

### Dashboard (`dashboard/app.py`, 1718 lines, in CI at `.github/workflows/platform.yml:35`)

- **GX-001** | Security hygiene | **Medium** | Confidence MEDIUM | Effort S. **The dashboard shell-sources the whole app secrets file as root.** `signup_admin()` (`dashboard/app.py:1583-1587`) runs `/bin/sh -c 'set -a; . "$1"; set +a; ... exec runuser -u agentai-platform -m -- ./.venv/bin/python manage.py signup_admin "$@"'` with `$1=/etc/agentai-platform/accounts.env` (`:1577`). Arguments are safe (argv list, `ACCOUNT_RE` at `:1578`, `isdecimal` at `:1614`), but the env file is evaluated as shell: any value with an unquoted metacharacter is executed by the dashboard user, and `-m` passes the entire sourced environment (every `AGENTAI_*` secret) to the child. The same file is written by hand-edited scripts (`bin/activate-telegram.py:52-53` appends `KEY=value` lines unquoted). The code also calls `os.geteuid() == 0` and `os.chown` (`:1245-1250`), so it expects to run as root, and it also has docker access via `docker exec` (`:269+`). Unit file is not in the repo (grep of `platform/deploy` and `deploy` finds only `ops/monitor.py` naming it), so privilege is UNVERIFIED. Recommended class F: parse the env with a non-shell reader, or pass only the vars `signup_admin` needs. Risk of change: low, covered by `CustomersPage` tests.
- **GX-002** | Security hygiene | **Low** | HIGH | S. **Login lockout is keyed on the TCP peer address, which is always loopback in the supported topology.** `do_POST` login (`:1004-1015`) counts failures per `self.client_address[0]`; the server binds `127.0.0.1` and is reached by SSH tunnel (`bin/owner-console.py`, `bin/open-ops-dashboard.py`), so every client is `127.0.0.1`. Five wrong passwords from any local process lock the owner out for an hour (`"wait an hour"`), a self-DoS. `_login_fails` (`:93`) is an unbounded dict, reset only by restart. Not covered by a test: `grep -c 429 dashboard/test_dashboard.py` = 0. Class F.
- **GX-003** | Error handling | **Low** | HIGH | S. **Pre-auth request-body read trusts Content-Length.** `_form()` (`:735-738`) does `min(int(Content-Length or 0), 8192)`: a negative value passes `min` and `rfile.read(-1)` blocks until the peer closes; a non-numeric value raises `ValueError` (handler thread dies, no response). `/login` POST calls it before auth (`:1010` onward), so it is reachable unauthenticated by any local process. `ThreadingHTTPServer` with `daemon_threads` (`:1711-1712`) means threads accumulate. Loopback-only, so Low. The same unguarded `int(Content-Length)` pattern exists in `jev-browser/jevbrowse/dashboard.py:179` and `bin/owner-console.py:183` (`min(int(...), 512)`).
- **GX-004** | Performance / reliability | **Low** | HIGH | S. **Session store rewrites the whole sessions file on every authenticated request, non-atomically.** `validate()` calls `_save()` on every hit to bump `last` (`:194-209`); `_save` opens with `O_TRUNC` then writes (`:180-182`), not temp-and-rename. A crash or concurrent kill mid-write leaves invalid JSON; `_load` swallows the error and returns `{}` (`:174-177`), silently signing everyone out (and the next `create` overwrites). Expired records are deleted only when that exact token is presented (`:203-206`), so abandoned sessions persist in the file (hashes only, `0600`). `/live/stream` and page loads multiply the writes. Class B/F. Tests exist for expiry and revoke-all (`Sessions` class) but not corruption.
- **GX-005** | Test debt | **Low** | HIGH | M. **Dashboard tests cover logic, not the handler's security edges.** 34 tests; grep counts in `test_dashboard.py`: `files/dl` 0, `live/stream` 0, `429` 0, `Content-Length` 0. Covered: workread containment (6), sessions (6), download-claim unit (2), redaction, switches and routing flows through the real handler (`FeatureSwitchesOverHttp`, `:332+`), customers page. Untested: the signed download route (`/files/dl`, `:894-912`: sig binding, `exp`, replay), the `/live/stream` Origin check (`:817`), lockout, `/toggle sandbox_browser`. Class: test debt.
- **GX-006** | Doc/architecture drift | **Medium** | MEDIUM | M. **Half the dashboard still drives the retired IONOS-era OpenClaw stack.** Hard-coded `BASE=/opt/openclaw-production`, containers `openclaw-production-openclaw-gateway-1` / `-postgres-1` / `-litellm-1` (`:66-76`), `docker exec ... node dist/index.js` for approvals, sessions, cron, audit, config (`:269,352,370,407,477,928,1068,1679`), spend from LiteLLM Postgres (`:311`).
